Mass-Issue-Closer

A Python command line tool, written after its author opened too many issues by hand, that closes every open issue in a single GitHub repository in one run, while leaving open pull requests untouched. This site is the line book: each arriving ticket gets a stamp, a stack, and a verdict.

The repo on GitHub The run

Line page one: intake conditions

Two things must be on the belt before the line starts.

A repository, named as owner/repository. The argument is optional: leave it out and the script uses the placeholder repository written in main.py, so pass a real owner/repository value for real use. A value that is not shaped like owner/repository is refused with exit 2 before any network call.

Access permission. Generate a classic GitHub personal access token with the repo scope, which includes public_repo for public repositories, and pass it as the first argument. One dependency is needed first:

pip install -r requirements.txt

That installs PyGithub. Running with no arguments prints the usage message and exits 2. The flags -h and --help print the full usage and exit 0, and they work even where PyGithub is not installed yet, because the import happens after argument parsing.

Line page two: the sorting

GitHub returns pull requests in the same list as issues. The tool checks each entry, and the two kinds get opposite verdicts.

Entry on the listVerdict
An open issueStamped for closing. One line printed per issue: Closed issue #N: title.
An open pull requestDiverted to the side belt. Skipped, never closed. One line printed per skip: Skipped pull request #N: title.

A finished pass ends with a summary line: Done, the count of issues closed, and the count of pull requests skipped.

Line page three: the run

python main.py INSERT_PAT_HERE [owner/repository]
1

Run with --dry-run first. It lists the issues that would be closed and the pull requests that would be skipped, printing Would close lines, and closes nothing.

2

A bad token or an unknown repository prints the API error and exits 1, before any close happens.

3

If a run stops early, most often on GitHub API rate limits, simply rerun it. Issues already closed are not returned again, so the rerun continues with what is still open. Tests run with python3 -m unittest against fake issues and a fake PyGithub module: no network, no real token.

Back cover: cautions, in the line book's last hand

Closing cannot be undone in bulk, and this script does not undo it. Confirm the repository name twice before running, the way the line crew reads a ticket twice before the stamp falls, and run --dry-run first.

Because the token is passed on the command line, it may be saved in your shell history. The script cannot clear its parent shell's history, so clear it yourself afterwards if that is a concern.
